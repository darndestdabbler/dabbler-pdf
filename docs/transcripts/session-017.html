Work Plan

Embed only the glyphs an Identity-H TrueType font uses. A new internal class TrueTypeFontSubSet (src/DabblerPdf/Text/TrueTypeFontSubSet.cs), ported from OpenPDF's TrueTypeFontSubSet, builds a TrueType font program from the original file holding glyph 0, every glyph the writer recorded, and every component of a composite glyph among them, recursively; glyph IDs keep their numbers (an unused glyph's outline is empty in a rewritten loca/glyf), so /CIDToGIDMap /Identity and /W stand. It writes head (checkSumAdjustment recomputed), hhea, maxp, loca, glyf, hmtx, and cvt , fpgm and prep when present, each with its checksum, padded to four bytes, in a valid table directory. TrueTypeFontUnicode.WriteFont writes that subset as FontFile2 at Close, and its /BaseFont (CIDFont and Type0) and the descriptor's /FontName take a subset tag of six uppercase letters and '+' (ISO 32000-1, 9.6.4), derived from the used glyphs. TrueTypeFont's private TtfReader becomes internal so the tests can parse the subset back, and AddFontDescriptor takes the font program and name it embeds, so the WinAnsiEncoding path keeps embedding the whole file under its plain name.
