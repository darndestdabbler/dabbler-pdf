Session 16: TrueType fonts with Identity-H draw any character the font has

  1. Register.
  2. BaseFont.CreateFont(ttfPath, BaseFont.IdentityH, true) today returns the same Windows-1252 font as WinAnsiEncoding (the encoding argument only keys the cache), and BaseFont.IdentityH's doc says "not yet implemented". Make it return a Unicode TrueType font, a new internal class beside TrueTypeFont (ported from OpenPDF's TrueTypeFontUnicode), that:
  • measures each character by its own glyph's advance, through the font's cmap and its full hmtx (not a 256-entry table); a character the font has no glyph for, and a surrogate pair, is glyph 0 (.notdef) and measures as its advance; CanEncode is true exactly when the font has the glyph;
  • is drawn by ShowText as 2-byte glyph IDs in a hex string (<0024004B> Tj), which needs PdfContentByte to know the font set by SetFontAndSize;
  • is written as a Type0 font, /Encoding /Identity-H, whose descendant is a CIDFontType2 with /CIDSystemInfo (Adobe, Identity, 0), /CIDToGIDMap /Identity, the font descriptor with the font file as FontFile2, a /W array for the glyphs used, and a /ToUnicode CMap that maps each used glyph back to its characters, so copying, searching and text extraction get the text.

/W and /ToUnicode depend on everything the document draws, so the writer reserves the font's reference when the font is first set and writes its objects at Close, from the glyphs recorded for that writer. A BaseFont is shared across documents by CreateFont's cache, so the used-glyph record lives in the writer, not the font. The writer keys font objects by PostScript name today, so the same .ttf used with both encodings in one document needs two resources: key them so it gets two. A Base 14 font with IdentityH throws ArgumentException: it has no glyphs to embed. The WinAnsiEncoding TrueType path is unchanged. The tests go in a file named after the new class, using the Liberation Sans fixture: a Polish, a Cyrillic and a Greek string are drawn and PdfPig extracts exactly that text from the page; the measured width of a string is the sum of its glyphs' advances; a character the font lacks (a CJK ideograph) measures as .notdef and CanEncode is false; one font drawn in two documents gives each document its own /W; the same file with both encodings in one document draws both texts; text drawn into a PdfTemplate is extracted too. Update BaseFont's docs for IdentityH, WinAnsiEncoding and CreateFont, and the README's Font Support section: how to draw Unicode text, what it covers, and its limits (no shaping, no right-to-left, no characters beyond U+FFFF, the whole font file embedded until Session 17).
